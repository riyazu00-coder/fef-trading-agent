## 1. Overview & Architecture of In-App Notifications

The FEF CORTEX In-App Notification engine delivers instant visual and audio alerts to traders through the Opportunity Radar and Cockpit UI. The lifecycle comprises 5 verified stages:
1. **Candidate Opportunity Generation:** Generated by the background scanner and multi-asset pipeline.
2. **Transition Engine State Machine:** Transitions asset from `MONITOR` $\rightarrow$ `FORMING` $\rightarrow$ `CONFIRMED`.
3. **Notification Persistence:** Stored in persistent browser `localStorage` and dispatched via pub/sub events.
4. **Frontend Consumption:** Subscribed components (TopNav badge, Toast alerts, Opportunity Drawer) render actionable setup cards.
5. **Deduplication Cooldown:** 15-minute symbol cooldown prevents alert fatigue.

  - `title`: `High Confluence Opportunity: Gold / US Dollar (BUY)`
  - `read`: `false`

### Stage 3: Notification Persistence
- Notifications are serialized into `fef_radar_notifications` key.
- Verified stored array length incremented by 1.
- Event payload matches strict schema without data corruption.

### Stage 4: Frontend Consumption & Pub/Sub Dispatch
- `subscribeToRadarNotifications` listener receives the new notification event within 1 millisecond.
- TopNav alert badge count updates from `N` to `N + 1`.
